README.md

# Pocket Garden A simple, persistent web application to track your indoor plants and watering schedules. ## How to Run 1. Download `index.html`. 2. Double-click to open it in Chrome, Firefox, Safari, or Edge. 3. No server or installation required. ## Features - **CRUD:** Add, Edit, and Delete plants. - **Persistence:** Data is saved to your browser's LocalStorage. It will be there when you come back. - **Watering Intelligence:** Calculates urgency based on last watered date and frequency.

ANSWERS.md

### 1. How to run Simply download the provided `index.html` file and open it in any modern web browser (Chrome, Edge, Firefox, Safari). It runs entirely client-side with no build steps or dependencies. ### 2. Stack choice I chose **Vanilla JavaScript + LocalStorage** inside a single HTML file. - **Why:** It is the most portable, lightweight, and "human-readable" stack for a mini-app. It requires zero environment setup for the reviewer. - **Worse choice:** A full React/Node stack with MongoDB. This would be overkill, difficult to run "fresh" without docker/scripts, and hides the logic behind build tools. ### 3. One real edge case **Handling the "First Run" / "Never Watered" state.** - **File:** `index.html` (inside the script logic). - **Explanation:** When a plant is created, `lastWatered` is set to `null`. The app checks if `lastWatered` is null and treats it as "Thirsty" immediately, rather than crashing on a date calculation. Without this, the math `(today - null)` would result in NaN or incorrect "days ago" rendering. ### 4. AI usage - **Tool:** ChatGPT (GPT-4). - **Prompt:** "Give me a CSS animation for a pulsing warning badge that isn't too annoying." - **Output:** It gave a keyframe animation changing opacity. - **My Change:** I added a `transform: scale(1.05)` to the pulse and slowed the duration to 2s to make it feel like a heartbeat rather than a strobe light, which feels more organic for a plant app. ### 5. Honest gap The search functionality is missing. Currently, if you have 50 plants, you have to scroll to find them. - **Fix:** I would add a client-side filter input that listens to `keyup` and hides DOM elements that don't match the plant name string.
